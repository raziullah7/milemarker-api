## What was checked and found sound

- **Fresh-clone path.**
  - `.gitattributes` forces LF, so `docker/entrypoint.sh` runs from a Windows checkout.
  - The supplied CSVs are stored byte for byte.
  - `uv.lock` holds Linux x86-64 and aarch64 wheels for numpy, scipy and psycopg-binary, so an Apple Silicon reviewer can build.
  - The image runs as the non-root `app` user, with the code owned by root.
  - `exec` makes gunicorn PID 1, and `set -e` stops on a failed migrate or load.
  - `load_stations` replaces the table in one transaction, so a restart is idempotent.
- **The running stack.**
  - `docker compose config` matches the file.
  - The image layers match the Dockerfile.
  - The API log shows the documented loader counts (8,151 / 6,738 / 6,626 / 6,615 + 11 / `Saved: 6626`), then `Listening at: http://0.0.0.0:8000`, as the README says.
- **API behaviour (requests sent).**
  - Dallas to Houston returned 200 from the cache: `routing_calls` 0, `cache_hit` true, own 0.9 ms, about 10 ms round trip.
  - The body has the shape of architecture §11.
  - The cost arithmetic follows D-14 (23.96 × 2.864 = 68.62).
  - Missing, blank and out-of-range parameters give 400 `invalid_request` with `fields`.
  - An unknown place gives five suggestions. Anchorage gives 422 `outside_coverage`. Start equal to finish gives 400.
  - POST and DELETE give a JSON 405. Unknown paths and `/` give a JSON 404.
  - Both URL forms work with no redirect.
  - From the code, not sent: `Retry-After` is set on the 429.
- **README claims checked against the repository.**
  - The counts: 6,626 stations, 29,880 places, 8,151 rows.
  - **348 tests plus 1 slow test**, counted statically: 337 literal cases, plus 5 more from the 6-entry `PURE_MODULES` list and 6 more from the 7 pinned trips.
  - `tests/verify.py` has 16 rules and imports only the standard library.
  - `live_check.py` has 49 cases (P01–P20, N01–N26, S01–S03).
  - EX-01 covers 400 trips and EX-02 covers 250.
  - The D-1 to D-15 table matches requirements §6, and the error table matches `STATUS_FOR_CODE`.
  - The example's stop arithmetic is consistent (39.21 × 3.239 = 127.00; 46.17 × 3.059 = 141.23).
  - The Compose commands and the layout table are correct.
- **Postman collection.**
  - It is valid v2.1 with one variable: 14 requests in three folders and 111 checks (counted). The run record agrees.
  - The cross-request checks are meaningful:
    - P02 is a cache hit with the same total.
    - P03 equals P01's lowest bill to the cent.
    - P04's "not fewer stops and not cheaper" must hold for any exact optimiser as the stop cost rises.
  - The error requests check the full error body.
  - The map script is sound as code (see Q0a-14).
- **Documents.**
  - Architecture §4 matches the file tree.
  - §9 matches `trips/services/routing.py` (the retry rules, deadline, User-Agent and both templates).
  - §11's error table, and its HEAD/OPTIONS sentence, match the code.
  - §16 matches the README's known limits.
  - Every acceptance check in requirements §9 is mapped to evidence in test-cases §8.
  - `data/README.md`'s counts and licences are right: the MIT text is present, and the OSM attribution for the fixtures is present.
- **Repository.**
  - Annotated tag `v1.0.0` on HEAD, and one author identity using a no-reply address.
  - A search of every tracked file found no keys, tokens, machine paths or personal email.
  - `.env` and the research caches are ignored.
  - The largest file is the 1.75 MB places table.
  - `NUM_PROXIES: 0` does stop spoofing through `X-Forwarded-For` today.

## What could not be checked, and why

- **The test suite, an image build, a fresh clone start, and NYC to LA or any other new trip.** The brief forbids pytest, container changes and new trips. The test count is static, and the README's NYC to LA figures come from the records, not from observation.
- **The map script inside the Postman app.** Postman is not available here. The script was run in a browser with a stub of `pm.getData`. Two things remain open:
  - whether OSM's tile servers, which require a Referer, serve tiles to Postman's visualizer frame;
  - whether Postman's frame loads unpkg.
- **geojson.io with the full 5,594-point map.** This would need a new NYC to LA response.
- **The public GitHub repository, and whether `v1.0.0` was pushed.** No network request was made to GitHub.
- **Whether Django 6.1.3 and DRF 3.18.3 are the latest releases today.** PyPI was not consulted.
- **The `pg_isready` start-up race (Q0a-11) and the ufw bypass (Q0a-02).** Both are reasoned from the postgres image's entrypoint and Docker's documented behaviour; neither was reproduced.
- **Method notes.** To confirm Q0a-03 I ran one read-only `grep` inside the running API container through `docker compose exec`, against the installed Django. The browser check replaced the DOM of the cached Dallas to Houston page in memory and wrote no file.
